## نظرة عامة

تطبيق محاسبي **Offline-first** موجّه للسوق العربي (اليمن تحديدًا). يعمل بلا خادم
وبلا إنترنت، وكل البيانات مخزّنة ومشفّرة محليًا على الجهاز.

### الميزات الأساسية

| المجال | التفاصيل |
|---|---|
| **السندات** | صرف وقبض · إنشاء/تعديل/حذف · بحث وفرز · مرفقات صور |
| **الحسابات** | 4 أقسام (عملاء `11` · موردين `22` · بنك `33` · موظفين `44`) بترقيم تلقائي |
| **الصناديق** | متعددة · أرصدة افتتاحية · عملات مفعّلة لكل صندوق |
| **العملات** | YER · SAR · USD · AED · EUR — **بسعري صرف منفصلين** للحساب والصندوق |
| **التقارير** | العمليات · الحسابات · الصناديق · الصور — تحليلي وإجمالي |
| **الطباعة** | A4 بمحرك ترقيم يقيس ارتفاع الصفوف فعليًا · تفقيط عربي |
| **النسخ الاحتياطي** | JSON مشفّر AES-256 بكلمة سر · تذكير كل 7 أيام |

### ما هو **غير** موجود

هذا **دفتر سندات**، وليس نظام محاسبة كامل. لا يوجد:
دليل حسابات هرمي · قيود يومية عامة · ميزان مراجعة · قوائم مالية ·
فواتير · مخزون · ضرائب · سجل تدقيق · إقفال فترات · تعدد مستخدمين · مزامنة سحابية.

## التشغيل السريع

### المتطلبات
- Node.js 22+
- JDK 21 *(للبناء على أندرويد)*
- Android SDK 36 *(أو استخدم GitHub Actions)*

### الأوامر

```bash
npm install --legacy-peer-deps    # التثبيت (العلم مطلوب)
npm run dev                       # خادم التطوير → localhost:3000
npm run typecheck                 # فحص TypeScript
npm run lint                      # فحص ESLint
npm run build                     # بناء الويب → مجلد out/
npm run cap:sync                  # بناء + مزامنة مع أندرويد
```

> **ملاحظة:** `--legacy-peer-deps` ضروري بسبب تعارضات في تبعيات Next 16 مع Capacitor.

## قاعدة البيانات

**IndexedDB** — `proof-daftar-local-db` (الإصدار 3)

| المخزن | المحتوى | المفتاح |
|---|---|---|
| `meta` | الإعدادات · الحسابات · الصناديق · العملات | مفاتيح نصية |
| `paymentOperations` | سندات الصرف | `id` |
| `receiptOperations` | سندات القبض | `id` |
| `operationImages` | الصور المرفقة | `img:<type><id>_<ts>` |

**الفهارس:** `datetime` و `cashboxId` على مخزني السندات.

### فصل الصور — قرار معماري مهم

الصور **لا تُخزَّن داخل السند**، بل في مخزن منفصل والسند يحمل مرجعًا `img:...`.

```
100,000 سند بصور مضمّنة  →  4.3 جيجا في الذاكرة  ⛔
100,000 سند بمراجع        →  38 ميجا            ✅
```

**دوال التعامل معها:**

| الدالة | الوظيفة |
|---|---|
| `isImageRef(v)` | هل القيمة مرجع أم صورة مضمّنة؟ |
| `loadImage(ref)` | قراءة صورة واحدة *(مع cache من 40 عنصر)* |
| `loadImages(refs)` | قراءة دفعة *(للطباعة)* |
| `externalizeImage(op)` | نقل صورة مضمّنة إلى المخزن |
| `withResolvedImages(ops)` | إرجاع سندات بصورها الفعلية |

### الترحيل التلقائي

`migrateImagesToStore()` ينقل الصور القديمة عند أول فتح بعد التحديث.

**ضمانات السلامة:**
1. الصورة تُكتب وتُتحقق **قبل** تعديل السند
2. عند الفشل تبقى الصورة مضمّنة *(التطبيق يعمل طبيعيًا)*
3. لا يُعلَّم الترحيل منجزًا إلا بنجاح 100% *(فيُعاد في الفتح التالي)*
4. قراءة الصور القديمة مدعومة دائمًا

> 🔴 **مهم:** أي تغيير على بنية التخزين يجب أن يحافظ على التوافق مع النسخ الاحتياطية القديمة.

## الأمان

| الطبقة | التنفيذ |
|---|---|
| **تشفير البيانات** | AES-256-GCM على الحقول الحساسة *(الحساب · البيان · المرجع · الصورة)* |
| **مفتاح الجهاز** | عشوائي 256-بت في `localStorage`، يُستورد مرة واحدة |
| **النسخ الاحتياطي** | AES-256-GCM + PBKDF2 بـ **600,000** دورة |
| **حقن HTML** | `escapeHtml()` على كل قوالب الطباعة *(56 موضعًا)* |
| **لقطات الشاشة** | `FLAG_SECURE` — يُرفع مؤقتًا أثناء الطباعة فقط |
| **النسخ السحابي** | `allowBackup=false` + `dataExtractionRules` |
| **تشويش الكود** | R8 + ProGuard · إزالة كل `Log` و `console` |
| **التوقيع** | V1 + V2 + V3 + V4 |

### ⚠️ ملاحظة أداء حرجة

مفتاح تشفير القاعدة **يُشتق مرة واحدة** ويُحفظ في `dbCryptoKeyPromise`.

```ts
// ❌ لا تفعل هذا — PBKDF2 لكل سجل
const key = await deriveAesKey(pass, salt);

// ✅ افعل هذا
const key = await getDbCryptoKey();
```

> اشتقاق PBKDF2 لكل سجل يجعل فتح التطبيق يستغرق **دقائق** مع آلاف السندات.
> PBKDF2 مخصص لكلمة سر المستخدم في النسخ الاحتياطي فقط.

## محرك الطباعة

يبني HTML كامل ويطبعه عبر `WebView` الأصلي *(أو `iframe` كخطة بديلة)*.

### القياس الفعلي بدل التخمين

`measureRowHeights()` يبني جدولًا مطابقًا في عنصر مخفي ويقيس ارتفاع كل صف بالبكسل.

> **لماذا؟** عرض عمود البيان يختلف بين التقارير (43% · 31% · 22%)، والتقدير الرياضي
> كان يخطئ حتى **99%** فتفيض الصفحات.

```ts
A4_CONTENT_WIDTH_PX = 190mm − 4px(إطار) − 8mm(حشو)
PRINT_PAGE_UNITS    = 244mm   // بهامش أمان
```

> 🔴 **تحذير:** أي تعديل على أنماط الطباعة يجب أن يُطبَّق **حرفيًا** على
> `measureRowHeights` أيضًا — وإلا يختل ترقيم الصفحات.

### قواعد أخرى

- الإجمالي `<tfoot>` في **آخر صفحة من كل مجموعة** فقط
- عدّاد `إجمالي/الحالية` أسفل كل صفحة *(داخل التدفق لا `absolute`)*
- فوق **120 كيلو** حرف: النقل عبر ملف مؤقت لا الجسر
- فوق **1,200 مرفق**: الطباعة محجوبة *(حد سلسلة JS ~512 ميجا)*

### قواعد ذهبية

1. **الحفظ أولًا، العرض ثانيًا** — لا تُحدّث الواجهة قبل تأكيد الكتابة
2. **لا `catch` صامتة** — كل فشل يجب أن يظهر للمستخدم
3. **افحص المساحة** قبل أي كتابة *(`ensureSpaceForWrite`)*
4. **حافظ على التوافق** مع النسخ الاحتياطية القديمة
5. **أنماط الطباعة والقياس متطابقة** دائمًا
